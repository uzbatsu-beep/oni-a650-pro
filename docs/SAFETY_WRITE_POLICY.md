# ONI A650 PRO — безопасная запись Modbus FC06 (PR #8)

## Назначение

Защита выполняется **в Rust Backend**, непосредственно перед отправкой каждого кадра FC06. Этот программный барьер не является функцией функциональной безопасности и **не заменяет аппаратный аварийный останов, STO и защитные цепи оборудования**.

Вся запись отключена при старте приложения, смене соединения и после ошибок с неопределённым результатом.

## Порядок допуска FC06

1. Оператор должен явно отключить режим «Только чтение». Для физического ПЧ необходимо действующее соединение.
2. Запрещается Modbus broadcast (slave 0), любой адрес вне белого списка и **прямая запись EEPROM через обычный FC06** (`0x8xxx`, `0xCxxx`). Разрешены только документированные адреса управления `0x2000`, `0x2001` и RAM-адреса параметров со статусом `RW` во встроенном CSV.
3. Для **каждой физической операции записи** Rust выполняет **новый FC03, address=0x2100, count=1**. Использование ранее сохранённого состояния или UI-параметра `stopOnlyCode` для разрешения записи запрещено. Если ответ не получен / недостоверен, запись отменяется, режим «Только чтение» включается автоматически.
4. Для записи параметра F/H допускается состояние останова `2100H=4`. В режиме настройки `2100H=0` контроллер дополнительно читает выходную частоту `3000H` и повторно читает `2100H`. Оба запроса выполняются в одном сеансе перед FC06. Требуются нулевая частота и повторное подтверждение режима настройки. При изменении состояния, ненулевой частоте или ошибке чтения запись отклоняется. Правило действует при подключении по RS-485 и RTU over Ethernet.
5. Допустимы команды `0x2000`: 1 (прямое), 2 (обратное), 5 (останов с торможением), 6 (останов на выбеге), 7 (сброс аварии). Пуск/реверс — в состояниях 1 и 4; сброс ошибки — в 4 и 6. Команды вне списка запрещены.
6. Уставка `0x2001` допускается в состояниях 1/4 и ограничена 0..60000 raw (0..600.00 Гц). **Фактические ограничения F01.08/F01.09 и условия технологического процесса следует соблюдать отдельно**; верхний предел 600 Гц не разрешает превышать настройки ПЧ.
7. Для записи параметров Rust сверяет `int16/uint16/enum16`, масштаб и числовые минимумы/максимумы из встроенного каталога. Для `enum16` допустимы только значения, перечисленные в каталоге. Неизвестные типы и символьные/зависящие от другого параметра границы (например, `F01.08`) — **запрет записи до реализации достоверного разрешения границ**. Никаких автоматических замен ошибочных данных на 0.
8. Заблокированы потенциально разрушительные сервисные параметры: `F00.00`, `F00.04`, `F00.05`, `F00.19`, `F00.24` (пароли, сброс и копирование).
9. Таймаут FC06 или неверный echo означают **неизвестный результат записи**: автоматического повторения нет, связь и режим записи блокируются до повторной проверки и явного разрешения. Действия и отказы записываются в журнал аудита.

## Последствия для совместимости

Некоторые прошивки могут не отвечать на `0x2100`. Ранее пользовательский интерфейс использовал косвенную оценку состояния по частоте; **для безопасности записи такой эвристики недостаточно**. В таком случае этот релиз сохраняет возможность чтения, но блокирует запись, пока не будет подтверждён другой достоверный регистр состояния конкретной модели.

Для H00.02 и H00.03 конфигуратор читает зависимые пределы из RAM при предпросмотре и перед каждой записью. Частота подключения H00.02 должна лежать между H00.03 и F01.08, частота останова H00.03 — между нулём и H00.02. Если чтение предела завершается ошибкой, FC06 не отправляется. Для остальных параметров с неразрешёнными символьными пределами запись блокируется.

## Сохранение параметров в EEPROM

На вкладке «Параметры» кнопка «Сохранить в EEPROM…» открывает список подтверждённых записей RAM текущего сеанса. По коду можно добавить параметр, изменённый с панели ПЧ. При смене подключения список очищается.

После подтверждения Rust последовательно читает фактическое слово RAM каждого выбранного параметра F или H00, сравнивает его с предпросмотром и проверяет состояние ПЧ. По таблице А.4.3 руководства ONI для F03.00 адрес RAM равен `0x0300`, а адрес EEPROM — `0x8300`. В EEPROM отправляется фактическое слово RAM. Значения из редактора и профиля сами по себе в список не попадают. Параметры чтения, пароли, команды сброса, копирования и автонастройки исключены.

Для A650M все 47 пар адресов H00 сверены с отдельными полями RAM и EEPROM в таблице OniDriveStudio. Например, H00.06 хранится по адресам `0x4006` и `0xC006`. Сохраняются 44 настройки RW. H00.30, H00.39 и H00.40 доступны только для чтения, H00.41 в каталоге отсутствует. [Таблица A650M из OniDriveStudio](https://github.com/uzbatsu-beep/A650/blob/2aee97ef826fdb7452c8cc538f1474155afc05cc/docs/research/oni-studio-a650m-extracted.json)

Счётчик подтверждений отражает корректные ответы FC06. При изменении RAM параметр требуется прочитать заново. При отказе операция останавливается на текущей строке. При потере эха результат текущей записи неизвестен, автоматически повторять её нельзя. На стенде сохранность данных проверяют чтением RAM после штатного цикла питания.

## Приёмочные испытания

- Проверить, что при запуске, реконнекте и потере связи режим записи сброшен в Read-Only.
- В режиме Read-Only проверить отклонение `0x2000`, `0x2001`, RAM и EEPROM без передачи FC06.
- Для физического ПЧ с **остановленным двигателем** проверить чтение `0x2100` непосредственно перед тестовой безопасной записью; отклонение недопустимых raw-значений и enum.
- В режиме вращения проверить запрет любой записи `Fxx/Hxx`; команда останова должна оставаться доступной, когда состояние подтверждено.
- При обрыве RS-485/таймауте FC03 — FC06 не должен отправляться. При неопределённом результате FC06 — **без автоповтора**, дальнейшая запись должна быть заблокирована.
- Не проверять сброс к заводским настройкам на рабочем оборудовании: отказ по F00.04 подтверждается unit-тестом без физической записи.
- Все испытания с разрешёнными командами пуска/останова проводить на безопасном стенде под надзором ответственного специалиста, не использовать приложение как E-Stop.
